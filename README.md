# AnalystMock

AnalystMock - Telegram-бот для подготовки к собеседованиям на продуктового аналитика.

Я начал делать этот проект, потому что сам готовлюсь к собеседованиям. Мне хотелось не просто решать задачи, а тренироваться в формате интервью: получать вопросы, отвечать своими словами и понимать, где допустил ошибки.

## Возможности

- Тренировка из 3 вопросов.
- Темы: SQL, статистика, A/B-тесты и продуктовые метрики.
- Генерация вопросов по тексту вакансии.
- Оценка ответов от 0 до 10.
- Разбор ошибок и пример правильного ответа.
- История тренировок и статистика в SQLite.
- Возможность отметить спорную оценку через /flag.

## Технологии

Python 3.12, aiogram 3, SQLite, Pydantic, Docker.

Для работы с LLM предусмотрены два провайдера:

- OpenAI API - облачная модель. Планируем использовать как основной вариант.
- Ollama - бесплатный локальный запуск Qwen3 4B.

## Зачем нужна LLM

На собеседовании человек отвечает свободным текстом. Один и тот же правильный ответ можно объяснить разными словами.

Обычная проверка по ключевым словам здесь не подходит. LLM помогает составлять вопросы по требованиям вакансии, анализировать ответы и объяснять ошибки.

## Архитектура

Telegram Bot -> TrainingService -> LLM -> SQLite

TrainingService управляет тренировкой. LLM создаёт вопросы и проверяет ответы. SQLite хранит результаты.

Сейчас это последовательный сценарий с LLM, а не полноценная мультиагентная система.

В дальнейшем планируем разделить генерацию вопросов, оценку ответов и перепроверку спорных оценок. Отдельные агенты будем добавлять только там, где они действительно полезны.

## Запуск через Docker

Нужны Docker и Telegram-бот, созданный через @BotFather.

Скачайте проект:

```bash
git clone https://github.com/Muhammadali2712/analystmock-agents.git
cd analystmock-agents
```

Создайте файл настроек:

```bash
cp .env.example .env
```

Откройте .env и укажите TELEGRAM_BOT_TOKEN и ALLOWED_USER_IDS.

Telegram ID можно узнать через команду /me у работающего бота.

Соберите Docker-образ:

```bash
docker build -t analystmock .
```

### Вариант 1. OpenAI API

В .env установите:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=ваш_API_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Модель указана как пример. Перед использованием другого названия нужно проверить его поддержку в OpenAI API.

Для работы необходим API-ключ и доступный баланс OpenAI.

Запуск:

```bash
mkdir -p data
docker run --rm --name analystmock \
  -v "$PWD/.env:/app/.env:ro" \
  -v "$PWD/data:/app/data" \
  analystmock
```

Облачный режим предусмотрен в коде. Проверка с реальным платным API пока не завершена.

### Вариант 2. Локальная Ollama

Установите Ollama и загрузите модель:

```bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
```

В .env установите:

```dotenv
AI_PROVIDER=ollama
OLLAMA_MODEL=qwen3:4b-instruct-2507-q4_K_M
OLLAMA_BASE_URL=http://127.0.0.1:11434
```

Запуск на Linux:

```bash
mkdir -p data
docker run --rm --name analystmock \
  --network host \
  -v "$PWD/.env:/app/.env:ro" \
  -v "$PWD/data:/app/data" \
  analystmock
```

Ollama должна быть запущена на компьютере. Сеть host используется для доступа контейнера к локальному серверу Ollama.

Остановить бота можно через Ctrl+C. Одновременно должна работать только одна копия бота с данным Telegram-токеном.

## Проверка

Для локального запуска тестов:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Последняя проверка - 22 теста прошли.

Также удалось собрать Docker-образ, запустить Telegram-бота и получить вопросы по тексту вакансии через Ollama.

## Ограничения

- Локальная Qwen3 4B на CPU может работать медленно.
- LLM иногда ошибается при оценке ответов.
- Проверка SQL пока использует упрощённые правила и может давать неверные оценки.
- Отдельный агент для перепроверки оценок ещё не реализован.

Эти ограничения планируем исправлять в следующих версиях.
