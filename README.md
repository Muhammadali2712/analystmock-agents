# AnalystMock

Первая версия Telegram-бота для подготовки к собеседованиям на Product Analyst.
Проект рассчитан на закрытое тестирование двумя участниками.

## Что уже есть

- Тренировка по SQL, статистике, A/B-тестам или продуктовым метрикам.
- Быстрая смешанная тренировка и вопросы по тексту вакансии.
- Три вопроса за сессию, ответ одним текстовым сообщением.
- AI-разбор: оценка из 10, сильные стороны, ошибки, рекомендации и пример ответа.
- Личная статистика по темам и история последних пяти тренировок.
- Продолжение незавершённой тренировки после перезапуска.
- Отметка спорного разбора через `/flag`. Такие оценки исключаются из средних баллов.
- Доступ только по одному или двум Telegram ID. В группах бот не отвечает.

Python, aiogram, SQLite и OpenAI Responses API. По умолчанию используется
`gpt-4.1-mini`; модель можно изменить в `.env`, если она поддерживает Responses
API и Structured Outputs и доступна вашему API-проекту.

## Запуск на Ubuntu / Linux

Нужен Python 3.11 или новее. Локальная проверка выполнена на Python 3.12.
Распакуй архив и открой терминал в папке `analystmock`, где лежит этот README.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

Если Ubuntu сообщает, что модуль `venv` недоступен, установи пакет `python3-venv`
через пакетный менеджер своей системы и повтори создание окружения.

### 1. Создать бота

Открой [@BotFather](https://t.me/BotFather), отправь `/newbot`, задай название
AnalystMock и свободный username, оканчивающийся на `bot`. Если бот уже создан,
можно использовать его токен, остановив прежнюю программу, которая им управляла.

Открой `.env` в редакторе и заполни только `TELEGRAM_BOT_TOKEN`:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
OPENAI_API_KEY=
ALLOWED_USER_IDS=
OPENAI_MODEL=gpt-4.1-mini
DATABASE_PATH=data/analystmock.sqlite3
DAILY_AI_REQUEST_LIMIT=40
```

Сохраняй токен в своём `.env`. Не отправляй его в переписку и не загружай в Git.

### 2. Узнать ваши Telegram ID

Запусти:

```bash
.venv/bin/python -m analystmock
```

Пусть каждый из вас откроет своего бота в личном чате и отправит `/me`.
Бот вернёт каждому его ID. Пока список доступа пуст, AI-тренировки недоступны.
Останови программу через Ctrl+C и впиши оба ID в `.env` через запятую.

### 3. Подключить AI

Создай [ключ OpenAI API](https://platform.openai.com/api-keys) в своём API-проекте.
Для запросов нужен настроенный API-биллинг и доступ к выбранной модели.
Вставь ключ в `OPENAI_API_KEY` в локальном `.env`.

```dotenv
ALLOWED_USER_IDS=123456789,987654321
OPENAI_API_KEY=ваш_ключ_API
```

Числа в примере нужно заменить вашими ID. Остальные настройки оставь как есть.
Проверь заполнение без сетевых запросов и снова запусти бота:

```bash
.venv/bin/python -m analystmock --check
.venv/bin/python -m analystmock
```

Теперь отправь `/start` и выбери «По теме» → «SQL».
Оставь процесс запущенным: после закрытия программы бот перестанет отвечать.
На этом этапе отдельный сервер не нужен. Запускай только одну копию программы.

## Запуск на Windows

В PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m analystmock
```

Настрой токен, ID и ключ по шагам выше. Для проверки настроек добавь `--check`.

## Как пользоваться

Для вакансии отправляй текст обязанностей и требований, от 60 до 4000 символов.
Содержимое ссылок бот сам не загружает. Ответ на вопрос тоже отправляй одним
текстовым сообщением до 4000 символов. SQL и Python разбираются как текст,
код не выполняется.

После разбора нажми «Следующий вопрос». Если бот или сеть временно недоступны,
нажми `/start` после восстановления: сохранённый вопрос или разбор появится снова.
`/cancel` завершает текущую сессию, уже сохранённые результаты остаются в истории.
`/review` показывает последний разбор, `/progress` - статистику, `/help` - команды.

Вопросы, ответы и разборы хранятся локально в `data/analystmock.sqlite3`.
Не удаляй папку `data`, если хочешь сохранить прогресс. При переносе проекта
останови бот и перенеси папку `data` вместе с ним.
Текст вакансии, вопросы и ответы отправляются OpenAI для обработки.
API-запросы используют `store=False`; это не означает полного отсутствия
обработки или хранения данных провайдером по его правилам.

По умолчанию лимит составляет 40 попыток AI-запросов на участника в сутки.
Генерация трёх вопросов использует один запрос, каждый разбор - ещё один.
Ошибочные попытки тоже учитываются, автоматические повторы отключены.
Лимит сбрасывается в 00:00 UTC, то есть в 03:00 по Москве. Это ограничение
числа запросов, не денежный бюджет. Расходы проверяй в своём API-проекте.

## Проверка вдвоём

Каждый проходит пять тренировок по три вопроса. Проверьте оба режима запуска,
сохранение результатов и восстановление после перезапуска. Среди ответов
попробуйте правильный, неполный и явно ошибочный. Спорные разборы отмечайте
через `/flag`, затем сверяйте с заранее подготовленными решениями или
учебными материалами.

Средний балл AI не доказывает улучшение навыков. Для проверки пользы решите
новое задание по теме прошлой ошибки без подсказок и проверьте ответы друг друга.
В этой версии самостоятельность решения и учебный эффект не определяются
автоматически; такую проверку нужно провести и записать отдельно.

## Проверка кода

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют маршруты настоящего диспетчера aiogram с подставным транспортом,
доступ участников, изоляцию данных, три вопроса за сессию, продолжение после
перезапуска, повторные сообщения, ошибки API, лимиты и исключение спорных оценок.
Отдельно проверяется сериализация схемы и разбор HTTP-ответа SDK OpenAI.
Тесты не используют реальные ключи, не отправляют сообщения в Telegram
и не делают платных запросов. Качество ответов модели проверяется отдельно
после подключения вашего ключа.

## Файлы проекта

- `analystmock/bot.py` - команды, кнопки и доступ участников.
- `analystmock/service.py` - сценарий тренировки.
- `analystmock/ai.py` - запросы к модели и инструкции для оценки.
- `analystmock/models.py` - формат вопросов и разбора.
- `analystmock/db.py` - сессии, ответы, статистика и лимиты в SQLite.
- `analystmock/config.py` - настройки из `.env`.
- `analystmock/__main__.py` - запуск.
- `tests/test_bot.py` - автоматические проверки.
